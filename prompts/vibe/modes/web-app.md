## Mode: Web App

The user wants a **web app** — multi-screen, stateful interaction, likely
authentication and persistent data. Bigger than a form, broader than a
dashboard.

Default assumptions you can offer (and the user can override):
- Client-side routing across a handful of screens
- State store of some kind (component state for small, a store for larger)
- Backend or BaaS for persistence (mock first if not chosen)
- Auth flow if any user-specific data is involved
